## 为什么这么装（先看 3 分钟，能省你 3 小时）

| 决定                                               | 理由                                                                                            |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Python 用 **3.12**（在 `D:\ruanjian\Python 3.12.0`） | 你 PATH 里排第一的是 **3.14.0a1 预览版**，numpy 生态在上面会炸。3.12 已验证可用                                       |
| 虚拟环境建在 **D 盘**，不放桌面                              | ① C 盘只剩 19.9 GB；② 桌面路径含中文，个别包处理中文路径会出问题                                                       |

| 模型放 **D 盘**（`D:\llm\models`）                     | 5 个文件共 13.4 GB。你的 D 盘剩 39.7 GB，够用；C 盘放不下                                                      |

## 第 0 步：打开 PowerShell 并设置编码

**目标**：有个能敲命令的窗口，且中文不乱码。

**怎么做**：

## 第 2 步：建虚拟环境（venv）

**目标**：得到一个干净的 Python 3.12，装什么包都不污染系统。

**为什么需要它**：不同项目要的库版本常常互相冲突。虚拟环境就是一个"专属小房间"，里面装的库只对当前项目生效。以后 `pip install` 全在这个房间里，不会把你系统里的 Python 搞坏。

**怎么做**：

```powershell
& "D:\ruanjian\Python 3.12.0\basepython\python.exe" -m venv D:\llm\venv
```

> ==_命令开头的 `&` 是 PowerShell 的"调用运算符"：路径带空格时必须加，否则会把路径当字符串。
> 这是新手第一个高频报错点，记住它。_==

**✅ 验收**：

```powershell
& "D:\llm\venv\Scripts\python.exe" --version
```

必须输出 `Python 3.12.0`。

**⚠️ 如果报 `ensurepip` 相关错误**：说明那个 3.12 安装不完整。先试
`& "D:\ruanjian\Python 3.12.0\basepython\python.exe" -m ensurepip --upgrade`，再重跑上面的建环境命令。

**约定**：以后所有命令都用 `& "D:\llm\venv\Scripts\python.exe"` 的方式调用，**不激活环境**。
理由：PowerShell 的脚本执行策略经常拦截激活脚本，而这台机器上"不用激活"完全不影响使用。

## 第 4 步：下载并解压 llama.cpp

**目标**：拿到 `llama-server.exe`、`llama-cli.exe`、`llama-bench.exe` 和 CUDA 运行库。

### 4.1 下载两个压缩包

我要用的版本是 **b11669**（2026-10-15 发布，已验证存在）。**两个包都要下，缺一个会闪退**：

```powershell
cd D:\llm\bin
curl.exe -L -o llama-cuda.zip "https://github.com/ggml-org/llama.cpp/releases/download/b11669/llama-b11669-bin-win-cuda-12.4-x64.zip"
curl.exe -L -o cudart.zip     "https://github.com/ggml-org/llama.cpp/releases/download/b11669/cudart-llama-bin-win-cuda-12.4-x64.zip"
```

| 文件                                       | 大约大小   | 是什么                      |
| ---------------------------------------- | ------ | ------------------------ |
| `llama-b11669-bin-win-cuda-12.4-x64.zip` | 267 MB | 可执行文件（CUDA 12.4 编译版）     |
| `cudart-llama-bin-win-cuda-12.4-x64.zip` | 391 MB | CUDA 运行时 DLL，**没它启动就闪退** |

> **版本会漂移**：上面的链接如果 404，去 <https://github.com/ggml-org/llama.cpp/releases>
> 找最新的 `b#####` 开头的版本，页面里选 **Windows x64 (CUDA 12)** 和它的 **CUDA 12.4 DLLs**。
> **不要选 CUDA 13**（你的驱动不支持）。

### 4.2 解压到同一目录

```powershell
cd D:\llm\bin
Expand-Archive -Path llama-cuda.zip -DestinationPath . -Force
Expand-Archive -Path cudart.zip     -DestinationPath . -Force
```

> 两个包都解压到 **同一个** `D:\llm\bin`。解压后目录里应该同时有 `.exe` 和一堆 `.dll`。
>
> **不需要再套子目录**（比如 `D:\llm\bin\llama-cuda`）。检查脚本会自动在
> `D:\llm\bin`、`D:\llm\bin\llama-cuda`、以及 `D:\llm` 下递归找，
> 但**exe 和 dll 必须待在同一个目录里**，分散放一定闪退。

**✅ 验收 1：文件在不在，以及大小对不对**

```powershell
dir D:\llm\bin\llama-server.exe, D:\llm\bin\llama-bench.exe
dir D:\llm\bin\*.dll | Measure-Object
```

- `llama-server.exe` 显示 **9,216 字节（约 9 KB）是正常的**——这些 exe 只是"壳"，
  真正的代码在 `llama.dll`、`ggml-cuda.dll`（约 549 MB）、`cublas64_12.dll`（约 95 MB）里。
  **不要因为只有 9 KB 就以为没下完。**
- DLL 数量应该 **30 个以上**。

**✅ 验收 2：能不能跑、能不能看到显卡（这一步最关键）**

```powershell
cd D:\llm\bin
.\llama-server.exe --version
.\llama-bench.exe --list-devices
```

期望输出：

```
version: 0.7.0-dev (build 11669, commit 620d2225c)      ← 第一行长这样
...
CUDA0: NVIDIA GeForce RTX 4060 Laptop GPU (8188 MiB, ...)   ← 第二项长这样
```

- **`--version` 报错或闪退**：① 缺 CUDA 运行库 DLL（重做 4.2 步）② 缺 VC++ 2015-2022 Redistributable。
- **`--list-devices` 只显示 CPU**：说明 DLL 没放对，检查同目录下有没有 `cudart64_12.dll`、`cublas64_12.dll`。

### 5.3 校验字节数（这一步别省，下到半截的文件会让你排查一整晚）

```powershell
Get-ChildItem D:\llm\models\*.gguf | Select-Object Name, Length | Format-Table -AutoSize
```

必须与下表**完全一致**：

| 文件                                               | 字节数           | GB   |
| ------------------------------------------------ | ------------- | ---- |
| `qwen2.5-1.5b-instruct-q4_k_m.gguf`              | 1,117,320,736 | 1.12 |
| `qwen2.5-1.5b-instruct-q8_0.gguf`                | 1,894,532,128 | 1.89 |
| `qwen2.5-3b-instruct-q4_k_m.gguf`                | 2,104,932,768 | 2.10 |
| `qwen2.5-3b-instruct-q8_0.gguf`                  | 3,616,088,480 | 3.62 |
| `qwen2.5-7b-instruct-q4_k_m-00001-of-00002.gguf` | 3,993,201,344 | 3.99 |
| `qwen2.5-7b-instruct-q4_k_m-00002-of-00002.gguf` | 689,872,288   | 0.69 |

**合计 13.41 GB。**

> **为什么网格里没有 7B 的 Q8？**
>
> 先把单位掰清楚（这一步很多人栽在上面）：
>
> | 量 | 十进制 GB | 二进制 GiB |
> |---|---|---|
> | 7B-Q8 权重 | 8.10 GB | **7.54 GiB** |
> | 你的显存 8188 MiB | 8.59 GB | **8.00 GiB** |
>
> 只看权重，7.54 GiB < 8.00 GiB，好像装得下。但还要减掉三块：
> KV cache（每 token 56 KiB，512 上下文约 28 MiB）、
> 计算缓冲（约 0.2–0.3 GiB）、
> 以及 Windows 桌面/WDDM 通常占用的 0.3–0.5 GiB。
>
> 算下来余量几乎是零：**实际加载大概率 OOM；即使勉强加载，也只能跑极小上下文**，
> 而网格里最小的一格就是 512 上下文——它放不进去。
> 所以它不是"理论上绝对不行"，而是"在这台机器上做实验不可行"。这本身就是项目里
> "约束剪枝"的第一个真实例子——写进报告，并在报告里把这段算账过程写出来。

**下载失败怎么办（三个备选，按顺序试）**

**备选 1：直链下载（绕过 CLI，最稳）**

一次把 6 个文件全下，断了重跑会自动续传（`-C -`）：

```powershell
cd D:\llm\models
$base = "https://modelscope.cn/models"
$pairs = @(
  "Qwen2.5-1.5B-Instruct-GGUF|qwen2.5-1.5b-instruct-q4_k_m.gguf",
  "Qwen2.5-1.5B-Instruct-GGUF|qwen2.5-1.5b-instruct-q8_0.gguf",
  "Qwen2.5-3B-Instruct-GGUF|qwen2.5-3b-instruct-q4_k_m.gguf",
  "Qwen2.5-3B-Instruct-GGUF|qwen2.5-3b-instruct-q8_0.gguf",
  "Qwen2.5-7B-Instruct-GGUF|qwen2.5-7b-instruct-q4_k_m-00001-of-00002.gguf",
  "Qwen2.5-7B-Instruct-GGUF|qwen2.5-7b-instruct-q4_k_m-00002-of-00002.gguf"
)
foreach ($p in $pairs) {
  $repo, $file = $p -split '\|'
  Write-Host "==> $file"
  curl.exe -L -C - -o $file "$base/$repo/resolve/master/$file"
}
```

下完再跑一次 5.3 的校验命令，6 个文件的字节数必须完全对上。

## 第 7 步：第一次让它说话（本阶段的仪式感）

**目标**：亲眼看到中文从你自己的机器上流出来，并记下第一组性能数字。

```powershell
cd D:\llm\bin
.\llama-cli.exe -m D:\llm\models\qwen2.5-3b-instruct-q4_k_m.gguf -ngl 99 -p "用三句话解释什么是内存带宽。" -n 80 --no-warmup
```

**输出长这样**（这是在你机器上实测的真实输出，不是示意）：

```
> 用三句话解释什么是内存带宽。
内存带宽是指计算机内存在一个单位时间内传输的数据量，它直接影响到计算机处理数据的速度和效率。

[ Prompt: 1291.7 t/s | Generation: 100.9 t/s ]
```

**怎么读这两行数字**：

| 字段 | 含义 | 等于我们后来要的 |
|---|---|---|
| `Prompt: ... t/s` | **prefill 速度**（一次算完整个提示） | 对应 TTFT |
| `Generation: ... t/s` | **decode 速度**（一个一个往外蹦） | 对应 TPOT 的倒数 |

3B-Q4 的 `Generation` 实测约 **90–110 t/s**（你这台机器是 100.9）。
**记下这个数**，S1 篇要用它反推带宽。

> **`--perf` 这个版本不再打印旧式的 `llama_perf_context_print: eval time = ...` 块。**
> 在这个 build（b11669）里，性能数字就是上面那行 `[ Prompt: ... | Generation: ... ]`。
> 我文档里原来引用的 `llama_perf_context_print` 是老版本的输出，已经过时——已按实机输出改正。

**如果想看"权重到底占了多少显存"**，加 `-lv 4`（提高日志级别）：

```powershell
cd D:\llm\bin
.\llama-cli.exe -m D:\llm\models\qwen2.5-3b-instruct-q4_k_m.gguf -ngl 99 -p "hi" -n 4 -st -lv 4
```

在几百行日志里找这四行（实测值）：

```
I load_tensors:   CPU_Mapped model buffer size =   166.92 MiB
I load_tensors:        CUDA0 model buffer size =  1834.83 MiB
I llama_context:  CUDA_Host  output buffer size =     0.58 MiB
I sched_reserve:  CUDA_Host compute buffer size =    48.02 MiB
```

| 行 | 含义 | 为什么要看 |
|---|---|---|
| `CUDA0 model buffer size` | **权重在显存里占多少** | 3B-Q4 约 1835 MiB，不是文件的 2007 MiB——有 167 MiB 仍靠 mmap 留在主机内存 |
| `CPU_Mapped model buffer size` | mmap 的主机副本 | **不算显存**，别把它加进显存账 |
| `compute buffer size` | 计算缓冲区 | 我估显存时留的 0.6 GB 余量主要给它和临时张量 |
| `CUDA_Host` | 在 CPU 一侧的临时缓冲 | 有它是正常的 |

**两个常见疑问**：

- **为什么命令末尾要加 `-st`？** `-st` = `--single-turn`，跑完一轮就退出。
  不加的话会进入交互式聊天模式（显示 `> ` 等你输入），你得手动 Ctrl+C。
  > 注意：网上常见的 `-no-cnv` 在这个 build 里**不存在**，用了会直接报错退出。
- **为什么没看到 `load_tensors: offloaded 37/37 layers to GPU`？** 默认日志级别看不到，
  加 `-lv 4` 才会出现。它出现就说明所有层都上了 GPU。

**✅ 验收**：屏幕出现通顺中文 + 一行 `[ Prompt: ... | Generation: ... ]`，
且 `Generation` 在 90–110（3B-Q4）或 45–55（7B-Q4）区间。
