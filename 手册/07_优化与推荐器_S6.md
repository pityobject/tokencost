## 一、先补上被忽略的第三根轴：质量

### 为什么必须有这一步

如果没有质量约束，推荐器给出的答案永远是"最小的模型 + 最大的并发"。这在数学上没错，在工程上是废话——因为它的潜台词是"你不在乎答案对不对"。

真实约束是三角：

```
           成本 ↓
          /      \
         /        \
   延迟 ↓ ———————— 质量 ↑
```

换小模型/降量化 → 省钱 → 质量掉。所以必须把质量测出来。

### 怎么测（`tc_eval.py` 已经写好了）

60 道**可以自动判分**的题，四类六种：

| 题型 | 例子 | 判分方式 |
|---|---|---|
| 加法 | 723 + 450 | 取回答里第一个整数，比对 |
| 乘法 | 39 × 72 | 同上 |
| 比大小 | 373 和 833 哪个大 | 同上 |
| 倒序拼写 | 把 machine 倒过来 | 检查答案里是否含 `enihcam` |
| 字母计数 | machine 里有几个 s | 同上（取整数） |
| 排序 | 把 39, 67, 20, 33 排序 | 检查数字序列 |

题目由固定随机种子生成，**期望答案由 Python 直接算出**，所以判分完全客观、可复现、无法作弊。

```powershell

```

**耗时**：每个组合约 1–2 分钟（60 题 × 短回答），5 个组合共约 8 分钟。

**预期结果形态**（你的数字会不一样）：

| 模型 | 量化 | 准确率 | 解读 |
|---|---|---|---|
| 1.5B | q4 | 72% | 算术开始出错 |
| 1.5B | q8 | 85% | 量化损失明显 |
| 3B | q4 | 91% | — |
| 3B | q8 | 95% | — |

> **"在这类任务上，把模型换大一级的收益，大于把量化从 Q4 提到 Q8。"**

这就是"质量轴"存在的意义——它让"省钱"有了边界。

## 二、把三个约束写成一个优化问题

到这里，"推荐配置"严格来说是一个**约束优化**：

```
决策变量： (模型规模, 量化档位, 上下文上限, 并发数)
目标：     最小化  单位成本 = 1e6 / 吞吐        （吞吐由 S5 的模型给出）
约束：
  ① 显存：权重 + KV×上下文×并发 + 0.6 GB  <  8 GB        ← 非矩形可行域！
  ② 延迟：CVaR90(TTFT) ≤ 上限 ，CVaR90(TPOT) ≤ 上限
  ③ 质量：准确率 ≥ 最高准确率 − 3 个百分点
```

三个约束的性质完全不同，这是这个问题的"味道"所在：

| 约束 | 性质 | 为什么难 |
|---|---|---|
| 显存 | **硬约束、不可协商** | 超一点就直接 OOM，没有"稍微超一点"这回事 |
| 延迟 | **概率约束**（尾部） | 不能说"平均延迟够"，要说"90% 的请求够" |
| 质量 | **离散、不可微** | 只能枚举，不能求导 |

### 为什么用 CVaR 而不是 P99（写成正式理由）

延迟如果用"P99 ≤ 300 ms"来约束，它有两个问题：样本量不够时估不准；作为约束不可优化。
所以我们用 **CVaR90**（最差 10% 的平均值）作为代理：

- 它和 P99 同向（尾部越差，CVaR 越大）
- 它是**凸函数**，可以放进优化里
- 它对样本量的要求比 P99 低得多

这叫**风险度量**（risk measure），是运筹/金融里的标准工具。你一个本科生能用对，是加分项。

### 非矩形可行域：用数字感受一下

| 组合 | 权重 | KV（并发×上下文） | 合计 | 8 GB 结论 |
|---|---|---|---|---|
| 7B-Q4, 512, 并发 32 | 4.68 | 0.94 | 6.2 | ✅ |
| 7B-Q4, 8192, 并发 4 | 4.68 | 1.88 | 7.2 | ⚠️ 勉强 |
| 7B-Q4, 8192, 并发 16 | 4.68 | 7.52 | 12.8 | ❌ |
| 3B-Q4, 8192, 并发 32 | 2.10 | 9.67 | 12.4 | ❌ |

**同一个模型，短上下文能开 32 并发，长上下文只能开 4 并发。** 这就是"约束把可行域剪成非矩形"的直观含义——
也是为什么"我们的设计空间约有 10 个组合物理上不可行"这句话有分量。

### 参数怎么给

| 参数 | 含义 | 建议取值 |
|---|---|---|
| `--ttft` | 首字延迟上限（ms），按 CVaR90 判定 | 交互式应用 300–600；批处理 2000–3000 |
| `--tpot` | 出字间隔上限（ms），按 CVaR90 判定 | 阅读体验 50–80 还行；实时对话 30 以下 |
| `--prompt-mean` | 平均提示长度（token） | 短问答 256；长文档 2048 |
| `--prompt-sigma` | 提示长度的对数标准差 | 长度整齐 0.3；长短混杂 0.8 |
| `--min-acc-drop` | 允许比最高准确率低几个百分点 | 默认 3 |

### 输出怎么读

```
推荐配置：1.5B_q4_k_m_ctx512_c32
  预测首字延迟（90% 上限）   120.5 ms   （上限 600）
  预测出字间隔（90% 上限）     7.8 ms   （上限 60）
  预测吞吐                  4310.7 token/s
  预测成本                    232 GPU 秒 / 百万 token

对照：满足 SLA 的最贵配置是 3B_q8_0_ctx8192_c1，成本 18529（是推荐的 713.0 倍）

被判出局的原因分布：
  显存装不下              8 格
  质量不达标              6 格
  质量够但不满足 SLA      9 格
```

**最后这三行是最值钱的输出**：它把"为什么不能随便选"讲清楚了——**约束在剪设计空间**。

## 四、验证推荐器：决策后悔值（这一节决定项目的高度）

推荐器只是"按模型算"。真正的问题是：**它算对了吗？**

`tc_verify.py` 用的是**双盲式的评估协议**，这是整份材料里最专业的一段：

```
1. 推荐器只看预测值  → 从满足全部约束的格里挑"预测最便宜"的
2. 拿实测数据核对它挑的那个格
3. 再算"如果一开始就知道全部实测结果，最优点在哪"（oracle，事后诸葛亮）
4. 后悔值 regret = 推荐的成本 / oracle 的成本 − 1
```

```powershell
& "D:\llm\venv\Scripts\python.exe" tc_verify.py
```

### 怎么解释结果

| regret | 含义 | 说明什么 |
|---|---|---|
| < 5% | 推荐器几乎等于事后最优 | **模型足够好，12 个点能替代 50 个点** |
| 5%–15% | 有差距但可接受 | 模型在某个区域有偏差，写清适用域 |
| > 20% | 模型明显不足 | 回到 S5 做残差分析 |

同时它会输出"相对默认配置的成本降幅"。这就是你简历里那句：

> **"推荐器仅凭 12 点标定模型做出的选择，与事后用 108 格全量实测选出的最优配置相比，"
> **决策后悔值中位数 __%；相对默认配置（3B-Q8/并发4）成本下降 __%。"**

> **为什么"后悔值"比"我降低了 30% 成本"高级？**
> 后者只说自己好；前者说清了"我的决策离事后最优有多远"——这是决策科学的标准语言。
> 面试官听到"regret"这个词，会立刻知道你不是只会跑 benchmark。

## 七、实测结果（2026-10-31，已经把这一篇的"预期"换成了真值）

### 7.1 质量基准（400 题，`--n-per-kind 30`）

| 模型 | 准确率 | 95% CI |
|---|---|---|
| 7B-Q4 | **81.4%** | [74, 87] |
| 3B-Q8 | 77.1% | [70, 83] |
| 3B-Q4 | 76.4% | [69, 83] |
| 1.5B-Q4 | 75.0% | [67, 81] |
| 1.5B-Q8 | 70.0% | [62, 77] |

**所有区间重叠** → 诚实结论：在这套题上"换大模型"的质量收益**没有被显著测出**，
而成本差约 3 倍。这是可以写进报告的工程结论，不是失败。

> 踩过的坑（写下来免得你重犯）：
> ① 原提示词「只输出最后的数字」被大模型理解成「最后一位数字」（1173→3），
>    导致 7B 在加法上 0%、1.5B 反而 100% 的荒谬结果。改成「只输出一个阿拉伯数字」后恢复正常。
> ② 判定标记曾把"百分点"和"比例"混用（5pp 被误判成超出噪声），已改成比较 95% 区间是否重叠。
> ③ 质量底线曾设为 3pp，比 400 题的噪声（±6pp）还紧，导致 108 个配置只剩 1 格可选。
>    **正确做法：底线 ≈ 一个置信区间半宽（6pp）**，代码里已改为默认 6。

### 7.2 推荐器实测输出

SLA：首字 ≤600 ms、出字 ≤60 ms；质量底线 6pp。

| | 配置 | 成本（GPU·秒/百万 token） |
|---|---|---|
| 推荐 | 3B-Q4 / ctx2048 / 并发 1 | **9841** |
| 最贵合规 | 7B-Q4 / ctx8192 / 并发 1 | 20772（2.11 倍） |
| 相对默认配置（3B-Q8/2048/并发4） | — | 再省 **20%** |

决策后悔值：**中位数 0.0%、最大 0.5%**。

### 7.3 一个"有理由的不可行"

长文档场景（提示均值 2048 token、首字预算 1500 ms）**无可行配置**：
最接近的 3B-Q4/ctx8192 预测 TTFT **1576 ms > 1500 ms**。

> 这类结论要原样写进报告——"跑不出来"和"物理上做不到"是两件事，后者是有效结论。
