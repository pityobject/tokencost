## 两个口径，别混用

- **墙钟吞吐** = 总 token ÷ 实测总耗时。端到端真实，但受"收尾空闲"与波次数影响
  （实测某格只有 1.33 波时，吞吐被低估 23%）。
- **稳态吞吐** = 并发 × 生成长度 ÷ 平均单请求生命周期。与波次无关，
  也正是解析模型预测的量。

**模型用稳态，端到端汇报用墙钟，两个都要报。**

## 原始数据的三条纪律

1. **永远不要手改 `raw_cells.jsonl`。** 发现某一格有问题就重跑那一格
   （`python code/tc.py run --only <模型> <量化> <ctx> <并发>`），让脚本重写。
2. **降频的格必须作废重跑。** 判据是「SM 时钟 < 2000 MHz **且** 功耗 < 50 W」——
   只看功耗会把高并发下 GPU 空转误判成降频。
3. **标定/留出划分写死在 `code/tc_config.py`**（`CALIB_CELLS`），跑之前就定好，
   不许看到结果再挑。本项目曾因跨模型族格混入留出集，导致对外数字与复现不一致。
