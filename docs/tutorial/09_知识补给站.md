## 二、Python：只补这 6 个点

### 2.1 f-string（会这一个，代码可读性立刻提升）

```python
name, n = "7B", 4.68
print(f"{name} 的权重是 {n:.2f} GB")      # 7B 的权重是 4.68 GB
print(f"误差 {0.0531*100:.1f}%")          # 误差 5.3%
```

`:>6` 右对齐、`:<7` 左对齐、`:>8.1f` 保留 1 位小数——代码里满屏都是这些，认识就行。

### 2.2 字典（项目的所有配置都是字典）

```python
spec = {"weight_bytes": 4_683_073_632, "n_params": 7.62e9}
print(spec["weight_bytes"])          # 取值
print(spec.get("missing", 0))        # 取不到给默认值
spec["new"] = 123                    # 新增
for k, v in spec.items(): ...        # 遍历
```

### 2.3 列表推导式（把循环写成一行）

```python
tpot = [r["tpot_ms"] for r in rows if r["ok"]]
```

**读法**：「对 rows 里每个 r，如果 ok 为真，取出 tpot_ms，组成一个列表」。

### 2.4 函数与默认参数

```python
def predict(bw, peak, ovh=1.5):     # ovh 有默认值
    return bw * peak + ovh
```

### 2.5 文件读写与异常

```python
with open("a.jsonl", encoding="utf-8") as f:   # with 会自动关文件
    for line in f:
        ...

try:
    do_something()
except Exception as e:
    print(f"失败：{e}")                        # 出错了不崩，记下来继续
```

> `encoding="utf-8"` **必须写**，否则 Windows 上读中文会乱码。这是本机最常见的坑。

### 2.6 async 只要"认识"，不用"会写"

```python
async def f(): ...
await asyncio.gather(*(f() for _ in range(8)))
```

**理解一句话就够**：`await` 表示"我在这儿等，但你可以先去干别的"。
项目里你只需要**会改参数**，不需要会从零写异步代码。

## 三、命令行：会这 10 条就够

| 命令 | 干什么 | 例子 |
|---|---|---|
| `cd` | 换目录 | `cd D:\llm\bin` |
| `dir` / `ls` | 列文件 | `dir *.gguf` |
| `mkdir` | 建目录 | `mkdir D:\llm\models` |
| `copy` / `Move-Item` | 复制/移动 | `Move-Item a.gguf D:\llm\models` |

**两个习惯**：
- 路径里有空格或中文 → **加引号**。
- 命令前有 `&` → 说明后面是可执行文件的路径。

## 五、统计：这是你和"只会跑 benchmark 的人"的分界线

### 5.1 分位数

第 90 百分位（P90）= 有 90% 的数比它小。代码里 `_pct(values, 0.90)`。

**必须知道**：用 20 个样本估 P99 是耍流氓——你估出来的其实是"最大值"。

### 5.2 CVaR（本项目的主风险指标）

```
CVaR90 = 最差 10% 那些样本的平均值
```

为什么用它：样本少时比 P99 稳；而且它是凸的，**可以进优化**。

### 5.3 标准差与"按比例看误差"

对数尺度：如果预测 100 实际 105，误差是 `ln(105/100)=0.049`；预测 1000 实际 950 是 `ln(950/1000)=-0.051`。
**对数尺度让"大值小值一视同仁"**——这是本项目损失函数的基础。

### 5.4 预测区间、t 分布、覆盖率

- 90% 预测区间：将来新观测有 90% 的概率落进去。
- 小样本用 **t 分布**（尾巴更厚）而不是正态（1.645）。
- **覆盖率**：拿留出集真的去数，落进区间的比例。要求 82%–96%：
  - 低于 82% → 你过于自信
  - 高于 96% → 你的区间宽得没有信息量

**自测**：如果我说"成本 400，90% 区间 380–421"，而 40 个检验点里有 24 个落进去，说明什么？
（答：覆盖率 60%，区间太窄，模型的不确定度被低估。）

### 5.5 MAPE

平均绝对百分比误差。本项目要求 ≤ 8%。

### 5.6 置信区间 vs 预测区间（别搞混，面试可能问）

- 置信区间：**参数**的不确定性（比如"带宽是 196±5 GB/s"）
- 预测区间：**下一个观测值**的不确定性（比如"下一格成本 400，可能 380–421"）

我们用的是后者，所以要把测量抖动也加进去。

## 七、大模型：只需要懂这 6 件事

### 7.1 token

模型处理的最小单位。1 个汉字 ≈ 0.65 token。**所有性能与成本都是按 token 算的。**

### 7.2 Transformer 在做什么（一句话版）

一串 token 进来 → 每一层做"自注意力 + 前馈网络" → 最后输出"下一个 token 的概率分布"。
参数就是那些矩阵里的数字，7B 模型有 76 亿个。

> 想看图：搜"The Illustrated Transformer"（Jay Alammar），只看前 2 节就够，不用看代码。

### 7.3 prefill 与 decode

- **prefill**：把整段 prompt 并行算一遍 → **算力密集**
- **decode**：一个一个往外蹦，每蹦一个都要读全部权重 → **带宽密集**

这一句是本项目的物理基础。

### 7.4 KV cache

存下历史 token 的 K 和 V，避免重复计算。**代价是显存**，8 GB 卡的真正约束。

会算：`2 × 层数 × KV头数 × 头维度 × 2 字节`（每 token）。

### 7.5 GQA（分组查询注意力）

多个 Q 头共享一组 KV 头，所以 KV 更小。这就是为什么 7B 每 token 只有 56 KB 而不是几百 KB。
**不用会推导，知道"它让 KV 变小了"就行。**

### 7.6 量化

用更少位数存权重。Q8 ≈ 1.06 字节/参数，Q4 ≈ 0.61 字节/参数。
**关键洞察**：量化让 decode 变快，不是因为它"算得快"，而是因为它**读得少**。
