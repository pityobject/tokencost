# S2 · 指标口径两道题（我的答案 vs 补齐版）

> 日期：2026-10-19 ｜ 面试前只看"补齐版"

---

## ① 为什么用 CVaR90 而不是 P99？

**我的原始答案**：P99 只给出最慢 1% 请求的阈值，CVaR90 衡量最慢 10% 请求的平均延迟。

**问题在哪**：这是**定义**，不是**理由**。面试官问的是"为什么不直接用 P99"。
定义说对了不加分，理由说不对会暴露"照文档抄的"。

**补齐版**：

> CVaR90 是最慢 10% 请求的平均延迟。选它而不用 P99 有两个原因：
> **第一是样本量**——我们每格只发 16–64 个请求，要可靠估计 P99 至少需要几百个样本；
> 用 24 个样本算 P99，得到的其实接近最大值，不是分位数。
> **第二是可优化性**——分位数不可导，没法放进优化器；CVaR 是凸函数，可以直接作为约束求最优配置。

**追问预案**："那你怎么保证 CVaR90 够狠？"→ 答：CVaR 和 P99 同向，
尾部一旦恶化，CVaR 立刻上升；而且我同时报 P50/P90/最大值，不做单一指标隐瞒。

## ② 为什么用「GPU 秒/百万 token」而不是「tokens/s」？

**我的原始答案**：一个是技术层面的吞吐量指标，另一个是单位成本指标。

**问题在哪**：这是循环论证——用"成本指标"解释"为什么用成本指标"。
而且没说清 tokens/s 到底哪里不够用。

**补齐版**：

> tokens/s 回答"多快"，但不回答"贵不贵"；而且它换模型、换上下文、换硬件都会变，
> 不同配置之间不可比。
> 我用 **GPU 秒/百万 token**（= 1e6 ÷ 吞吐），它把吞吐归一化成
> "生产 100 万 token 需要占用 GPU 多少秒"——乘以单价（元/GPU小时 ÷ 3600）就直接是钱。
> 更重要的是它**与硬件解耦**：搬到 A100 或昇腾，只需换单价那一行，模型和结论结构都不变。
> 另外它把 prefill 也算进去了（每条请求占用槽位的时间 = TTFT + 生成长度 × TPOT），
> 所以不同并发、不同上下文之间是可比、可加、可画在同一张 Pareto 图上的。

**追问预案**："那你们为什么还报吞吐？"→ 答：吞吐是中间量，便于和公开 benchmark 对照；
但所有决策都用成本，因为只有成本能换算成钱。

## 附：单格实测基准（3B-Q4 / ctx2048 / 并发4）

| 指标 | 实测 | 说明 |
|---|---|---|
| TTFT P50 | 262.8–272.1 ms | 并发 1 时只有 76 ms；差额来自 `2·P·L·b` 的 prefill 竞争 |
| TPOT P50 | 12.36–12.68 ms | 并发 1 时 9.7 ms；差额来自批处理效率 |
| 吞吐 | 270.4–278.4 tok/s | 不是 99.3×4=397，因为要扣批处理效率再扣 prefill |
| 单位成本 | 约 3600 GPU 秒/百万 token | = 1e6 ÷ 吞吐 |
| 客户端 CPU | 10% | 远低于 70%，客户端不是瓶颈 |
| 温度/频率 | 54.5–56.5 °C / 2400 MHz | 满频，无降频 |
