## 3. 本轮亮点：`tc_audit.py`

### 3.1 它检查什么

| 类别 | 检查项 | 对应失败模式 |
|---|---|---|
| **仓库卫生** | 已跟踪文件都在 / 无绝对路径 / 无超大文件 / 无密钥 | 换人 clone 就跑不起来 |
| **自包含** | 只把已跟踪文件复制到临时目录，能否跑通 claims 与测试 | 依赖了未提交的文件 |
| **数据链** | summary 可由 raw 重算 / fit 记录了留出格数 / quality 无空列 | 汇总表与原始数据对不上 |
| **契约** | 20 个 CLI 子命令目标存在 / 文档引用的文件存在 / 6 张图非空 / toml 合法 / Actions 配置存在 | 文档里指向空气 |

### 3.2 实跑结果（`--fast`，跳过裸克隆）

```
【1】仓库卫生   4/4 OK（436 个文件）
【3】数据链     3/3 OK（抽 6 格重算 summary，中位耗时一致）
【4】契约       5/5 OK（20 个子命令 / 所有 .md 引用 / 6 张图 / toml / Actions）
结论：12/12 项通过 ✅
```

### 3.3 完整模式我跑不了（环境限制，不是项目缺陷）

第 2 步裸克隆报：

```
PermissionError: [WinError 5] 拒绝访问
  File "...subprocess.py", line 1375, in _get_handles
    c2pread, c2pwrite = _winapi.CreatePipe(None, 0)
```

对照实验：

| 调用方式 | 结果 |
|---|---|
| `subprocess.run(..., capture_output=True)` | ❌ WinError 5 |
| `subprocess.run(...)`（不捕获） | ✅ 正常 |

**即我的沙箱禁止给子进程开管道**。所以"裸克隆自检"这一步我只能确认它写对了（逻辑是 `shutil.copytree` 已跟踪文件到 tempdir 后跑 claims/tests），无法在这里执行。

## 4. 新发现：两处"本地加了检查，没同步到远端"

### 4.1 🟠 GitHub Actions 比本地 CI 少两步

| 检查 | `scripts/ci.ps1` | `.github/workflows/ci.yml` |
|---|---|---|
| claims 生成 + 校验 | ✅ 1/3、2/3 | ✅ |
| 单元测试 | ✅ 3/4 | ✅ |
| doc lint（warning 级） | ✅ 4/5 | ❌ |
| project audit | ✅ 5/5 | ❌ |

README 把仓库同时挂在 Gitee 与 GitHub。别人看 GitHub 的绿勾会以为只跑了 3 项，而本地实际有 5 项。

### 4.2 🟡 `ci.ps1` 的步骤编号是拼的

```
[CI] 1/3  →  [CI] 2/3  →  [CI] 3/4  →  [CI] 4/5  →  [CI] 5/5
```

分母从 3 漂到 4 再到 5——分三次加步骤的痕迹。无功能影响，但显示在一个"处处讲究口径"的项目里有点扎眼。

### 4.3 🟡 v6 复核副本无状态头

`报告/第三方复核意见_第六轮_20261102.md` 里的 §6「剩余 3 件事」现在已经全部完成，但文件本身没有状态说明——读起来像"还有 3 件事没做"。

## 7. 一个观察：从这一轮起，判断标准变了

前六轮我做的其实只有两件事：**核对数字**、**追踪同一数字被写了几遍**。
这一轮开始，这两件事**项目自己能做了**：

| 以前的检查方式 | 现在 |
|---|---|
| 我手算 MAPE、对账 README | `tc_claims --check`（数字漂移即失败） |
| 我 grep 找过期数字 | `tc_lint_docs`（作废清单扫描 5 份文档） |
| 我逐条确认文件在不在 | `tc_audit`（20 个子命令 / 文档引用 / 图 / toml） |
| 我判断"换台机器能不能跑" | `tc_audit` 的裸克隆自检 |

**这是一个项目从"被人审"变成"能自审"的转折点。** 到这一步，对外材料的可信度已经不完全依赖作者的自觉了。
