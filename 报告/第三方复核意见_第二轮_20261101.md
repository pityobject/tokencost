**改法（二选一）**：

### 🔴 3.2 "决策后悔值"三处三个数，且三个都错

| 出处 | 写的 | 真值 |
|---|---|---|
| `results/CLAIMS.md` | **`nan%`** | — |
| `README.md:17` | 中位 0.0% / 最大 3.9%，"**区间宽度中位 1.1 pp**" | 区间宽度中位 **106.25 pp**（差 100 倍） |
| `报告 §3.6` | 中位 0.8% / 最大 3.3%，省 18%–37% | 中位 **0.00%** / 最大 **3.89%** |

**根因 1 —— 字段名对不上。** `tc_claims.py:50` 读的是中文列：

```python
regret = ver["后悔值"].dropna() if "后悔值" in ver else pd.Series(dtype=float)
drop   = ver["相对基线降幅"].dropna() if "相对基线降幅" in ver else pd.Series(dtype=float)
```

而 `tc_verify.py` 已改为输出 `regret_pct` / `default_drop_pct`。于是静默取空 → `nan%` → 写进"唯一数字源"。**这是"防漂移机制"自身失效的典型案例。**

**根因 2 —— bootstrap 区间可为负。** 例如 `[−0.082, +0.083]`、`[−0.554, +0.557]`。
后悔值的定义是 `pick_meas / oracle_meas − 1 ≥ 0`，**下限不可能 < 0**。说明重采样的对象不是后悔值本身（看起来是成本比之差），这个区间不能当 CI 引用。

**根因 3 —— 指标本身已被自己否定。** 审计第 52–53 节写得很清楚：

> "一旦固定质量档位与 SLA，成本最优解几乎完全由'最小可用模型'决定，**这个问题本身就没有排序难度**。
> 所以'后悔值≈0'是一个关于问题结构的结论，不是关于模型能力的结论。"

我在本轮也复核了分辨力：`n_cands ≥ 20` 的 32 行里，**30 行后悔值恰为 0，只有 2 行非零**。
→ 它不该继续留在 README 指标表的第 4 行当卖点。

**改法**：
1. 修 `tc_claims.py` 字段名（见 5.1）；
2. README 该行改成：`决策后悔值（本设计空间） | 中位 0.0% / 最大 3.9% —— 因候选集粗粒度，该指标几乎无分辨力`；
3. 若想让它重新有意义，**必须加负对照**：用 v1 三参数模型 / 参数扰动 ±2σ / 随机选，看后悔值能否涨起来。涨不起来 → 说明指标坏；涨得起来 → 才有资格说"我的模型决策更稳"。

### 🟠 3.4 防漂移机制有两个盲区

1. **自比对盲区**：`claims --check` 拿自生成的 `CLAIMS.md` 当基准，`CLAIMS.md` 自己错了（`nan%`）它一个字不说。
   → 必须加：**关键行不得为 `nan` / `—`，否则直接 FAIL**。
2. **硬编码盲区**：`tc_claims.py` 里三个值不是算出来的，是写死的字面量：

```python
"留出集格数（core 口径）": "68 格",
"标定并发上的 MAPE": "5.8%",
"未标定并发上的 MAPE": "11.5%",
```

`--population` 一变，这三个数就不会跟着变。→ 应写进 `fit.json` 再读，或从 `predictions.csv` 现算。
