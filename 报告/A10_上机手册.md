## 1.0 DSW 使用要点（先看这 6 条）

本手册针对**模型开发服务 → 交互式建模（DSW）**，它提供 JupyterLab / WebIDE / Terminal，
有 **sudo** 权限，额度 **250 计算时/月 × 3 个月（共 750）**，可抵扣三种机型。

| # | 要点 | 影响 |
|---|---|---|
| 1 | **只有"运行中"才计费** | 跑完立刻**停止实例**，额度就停止扣；不必马上释放 |
| 2 | **停止 ≠ 释放**：停止后系统盘与 `~/` 数据保留 | 下次开机能接着用已下载的模型 |
| 3 | **释放实例会删盘** | ⚠️ **下载完结果再释放**，否则白跑 |
| 4 | 有 sudo | 缺 cmake/依赖可直接 `apt-get`（脚本已处理 root/sudo 两种情况） |
| 5 | Terminal 入口 | JupyterLab 左上 `File → New → Terminal`；WebIDE 底部终端也可以 |
| 6 | 三种机型共用额度 | A10 与 V100 可以**分两天各建一个实例**，互不影响 |

> 一个实例跑完 ≈ 1.3 计算时，V100 再 ≈ 0.7 计算时；
> 750 计算时意味着**这块额度根本用不完**，请优先保证数据质量，不必省时间。

## 4. 一条命令跑完全流程（推荐）

```bash
cd ~/tokencost
bash scripts/a10_run.sh 2>&1 | tee ~/a10_full.log
```

**它会依次做 8 件事**，下面给出每件事的"预期现象"：

| 步骤 | 预期现象 | 大概耗时 |
|---|---|---|
| 0 环境 | 打印 GPU 名称与 23028 MiB | 10 s |
| 0.5 自检 | 与第 3 节相同的 `✅ 自检通过` | 1 min |
| 1 下模型 | 两个 ModelScope 下载进度条，最后 `模型下载完成` | 5–10 min |
| 2 编译 llama.cpp | 安静（输出重定向），最后进入下一步 | 8–15 min |
| 3 起服务 | 循环等 `/health`，起来了继续 | 30–60 s |
| **3.4 GPU 卸载校验** | 打印 `GPU 卸载确认：… offloaded N/N layers to GPU` | 5 s |
| **3.5 ctx 校验** | 打印 `日志里的 n_ctx_slot = 2304，期望 ≈ 2304` | 5 s |
| 4 标定 llama.cpp | 逐点打印并发/长度/延迟，最后 6 参数表 | 5–10 min |
| 6 起 vLLM | 打印 vLLM/torch 版本，等 `/v1/models` | 1–3 min |

> 脚本会自动用 `-c 2304` 重启。**看到"⚠️ 该 build 不按并发切分"是正常的，不是错误。**

## 6. 怎么判断这次真的跑成功了

### 6.1 两个结果文件都存在且参数合理

```bash
cd ~/tc_a10/results
python3 -c "
import json,glob
for f in sorted(glob.glob('calib_a10_*.json')):
    d=json.load(open(f))
    print(f, '| n_points', d['n_points'], '| bw %.0f'%d['bw'], '| c_srv %.3f'%d['c_srv'],
          '| mape %.1f%%'%(d['residual'].get('mape_tpot',float('nan'))*100))
"
```

> ✅ **检查点 6**：`n_points` ≥ 6；`bw` 在 **350–550 GB/s**（A10 标称 600 的有效值）；
> `c_srv` 是**正数且 < 20 ms**。

### 6.2 验收表（写进报告用）

| 检验 | 期望 | 不符说明 |
|---|---|---|
| ① A10 的 `bw` | 350–550 GB/s | 太低 → 带宽没用满 |
| ② A10+llama.cpp 的 `c_srv` vs 4060 的 0.766 | 实测差 2.0× | `c_srv` 还依赖主机 CPU，不只是栈 |
| ③ vLLM 的 `c_srv` vs llama.cpp | 差 >50% | 几乎相同 → 开销同源（也是结论） |
| ④ 两后端 6 参数都能拟合 | 各自 MAPE <15% | 拟合不上 → 模型形式依赖后端 |

### 6.3 把结果带回来（三选一）

1. **JupyterLab 左侧文件树** → `tc_a10/results/` → 右键 `Download`（最稳）
2. 终端 `cat` 出参数表，整段贴回来
3. 实例能联网且有凭据：`git add -A && git commit -m a10 && git push`

## 7. 故障排查（按现象查）

| 现象 | 原因 | 处理 |
|---|---|---|
| `看不到 GPU` | 规格选错 | 换 `ecs.gn7i-c8g1.2xlarge` |
| 下载模型卡住 | ModelScope 限速/网络 | 重试；或 `pip install -q modelscope -U` |
| 编译报 `nvcc not found` | 镜像没 CUDA | 换 PyTorch+CUDA 镜像，或 `apt-get install -y nvidia-cuda-toolkit` |
| `llama-server` 起不来，日志 `failed to allocate` | KV 太大（ctx 语义不切分） | 把 `--ctx-size` 改成 2304 |
| 健康检查 120 次都没过 | 端口占用 | `pkill -f llama-server`；换端口 8091 |
| 标定报 `prompt 超长` | PER_SLOT < 2048+128 | 用 2304，不要 2112 |
| TTFT 不随长度增长 | **缓存命中**（F9） | `tc_profile` 已加 nonce；若仍如此，查服务端日志 |
| vLLM 报 `CUDA driver version is insufficient` | 镜像 CUDA 太旧 | 换镜像；或 `pip install -q "vllm==0.6.*"` |
| 标定中途 `Killed` | 显存不足 | 降 `--max-num-seqs` 到 16，并在报告里注明 |
| 实例被回收 / 断连 | 免费额度用尽或超时 | 结果文件在 `~/tc_a10/results/`，重连后先 `ls` 确认还在 |

### 10.2 环境重建（新实例 / 环境被释放后）

**关键点：这台机器访问 GitHub / Gitee / ghproxy / gitclone 全部被 TLS 中断，但 PyPI 可用。**
所以 llama.cpp 源码从 **PyPI 源码包**拿，不从 GitHub clone：

```bash
# 1) 依赖
pip3 install -q -i https://mirrors.aliyun.com/pypi/simple/ gguf sentencepiece transformers

# 2) 从 PyPI sdist 取 llama.cpp 源码（内含完整 vendor/llama.cpp，约 74 MB）
rm -rf /tmp/lcp && mkdir -p /tmp/lcp
pip3 download llama-cpp-python --no-binary :all: --no-deps -d /tmp/lcp \
  -i https://mirrors.aliyun.com/pypi/simple/
cd /tmp/lcp && tar xzf llama_cpp_python-*.tar.gz
cp -r llama_cpp_python-*/vendor/llama.cpp /mnt/workspace/tc_a10/llama.cpp

# 3) 编译（8 vCPU 约 10–15 分钟）
cd /mnt/workspace/tc_a10/llama.cpp
cmake -B build -DGGML_CUDA=ON -DLLAMA_CURL=OFF -DCMAKE_CUDA_COMPILER=/usr/local/cuda/bin/nvcc
cmake --build build -j8 --target llama-server

# 4) HF 权重转 GGUF（用编译出来的转换脚本，约 1 分钟）
python3 llama.cpp/convert_hf_to_gguf.py /mnt/workspace/tc_a10/models/hf \
  --outfile /mnt/workspace/tc_a10/models/gguf/qwen3b-fp16.gguf --outtype f16

# 5) 起服务（注意：本 build 的 --ctx-size 是**总上下文**，必须 = 每槽 × 槽数）
llama.cpp/build/bin/llama-server -m models/gguf/qwen3b-fp16.gguf -ngl 99 \
  --ctx-size 73728 --parallel 32 --host 127.0.0.1 --port 8092

# 6) vLLM（镜像自带 torch 2.3.1，装 0.5.5 兼容；会顺带升级到 torch 2.4）
pip3 install -i https://mirrors.aliyun.com/pypi/simple/ "vllm==0.5.5"
python3 -m vllm.entrypoints.openai.api_server --model models/hf --served-model-name qwen3b \
  --max-model-len 2304 --max-num-seqs 32 --gpu-memory-utilization 0.9 --port 8081
```

### 10.3 今天踩过、必须记住的四个坑

| 坑 | 现象 | 正确做法 |
|---|---|---|
| GitHub/Gitee 被 TLS 中断 | `gnutls recv error (-9)` | 走 **PyPI 源码包**（上面第 2 步） |
| `--ctx-size` 语义 | `n_ctx_slot = 256`（被除没了） | 传**总上下文** `2304×32 = 73728` |
| GGUF 文件名 | 报"没找到 F16" | Qwen 仓库是 **`fp16`** 不是 `f16`；没有就直接转换 |
