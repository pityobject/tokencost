# 阿里云 2C4G 服务器使用方案

> 现状：CPU 1.41% / 内存 32.7% / 云盘 25.6% / 网络 1.16 Kbit/s —— **基本空闲**。
> 限制：**无 GPU**，所以 vLLM（B1）和跨卡验证（B2）都做不了，那两项需要按小时租 GPU。

---

## 一、它能做什么（按价值排序）

| # | 用途 | 价值 | 工作量 |
|---|---|---|---|
| **①** | **第三方复现验证**：在一台干净 Linux 上跑通全部自检 | ★★★★★ | 1–2 小时 |
| **②** | 托管 **A2 静态计算器**（公网链接） | ★★★★☆ | 半天（含写 HTML） |
| **③** | **CPU 跨机标定**：另一台机器上跑 `tc profile` | ★★★☆☆ | 1–2 小时（慢） |
| ④ | 作为"别人的机器"跑一次 `tc_audit`（含裸克隆） | ★★★☆☆ | 半小时 |

**为什么 ① 最值钱**：现在"可复现"的证据是 **自证**
（`claims --check`、`audit` 的裸克隆都在我这台 Windows 上跑）。
在一台**没有 D 盘、没有模型、没有 venv、不是 Windows** 的机器上跑通，才叫**他证**。

> 这条一旦做成，面试时可以讲：
> **"我在自己的 Windows 上跑通不算数。我又在一台干净的 Linux 云服务器上从零跑了一遍，四项自检全过。"**

## 三、② 托管静态计算器（A2 做好后）

等我把 A2 的单文件 HTML 写出来，部署只要：

```bash
# 方式 A：临时（重启失效）
cd ~/tokencost/site && python3 -m http.server 8080

# 方式 B：nginx（推荐）
sudo apt install -y nginx
sudo cp index.html /var/www/html/
sudo systemctl enable --now nginx
```

然后**阿里云控制台 → 安全组 → 放行 80 端口**，就能得到 `http://<公网IP>/`。

> 这一步的产出是一个**链接**：面试时"打开这个网址，输入你的 SLA"比讲十分钟更有用。

## 四、③ CPU 跨机标定（可选，别期待太高）

```bash
# 装 llama.cpp（源码编译，2 核大约 10–20 分钟）
cd ~ && git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp && cmake -B build -DLLAMA_CURL=OFF && cmake --build build -j2

# 下模型（0.5B Q4 只有 0.46 GB，适合这台机）
pip3 install -U huggingface_hub
HF_ENDPOINT=https://hf-mirror.com python3 -c "
from huggingface_hub import hf_hub_download as d
d('Qwen/Qwen2.5-0.5B-Instruct-GGUF','qwen2.5-0.5b-instruct-q4_k_m.gguf', local_dir='~/models')"

# 起服务
~/llama.cpp/build/bin/llama-server -m ~/models/qwen2.5-0.5b-instruct-q4_k_m.gguf \
  -c 2048 -np 4 --host 127.0.0.1 --port 8080 &

# 标定
cd ~/tokencost/code
python3 tc_profile.py --base-url http://127.0.0.1:8080/v1 \
  --spec-json ~/myspec.json --hardware "阿里云 2C4G (CPU)" \
  --concs 1,2,4 --lengths 128,512 --requests 4 --gen 16
```

> `--spec-json` 需要填 0.5B 的规格：`weight_bytes`（GGUF 文件大小）、`n_params=494000000`、
> `n_layers=24`、`n_kv_heads=2`、`head_dim=64`（以 HuggingFace config 为准）。

**预期与限制（先说清楚）**：

- 这台机是 **CPU**，而六参数模型是**面向 GPU 的 roofline**。已有的 CPU 迁移误差是 **27%**，
  所以这里大概率还是会差 20–30%。
- 因此这项的价值**不是"验证性能迁移"**，而是：
  1. 验证**标定协议**能不能在另一台机器上跑通（`tc_profile` 的跨机可用性）；
  2. 给"CPU 栈"多一个样本，看 27% 是不是稳定量级。
- **不要**据此声称"换硬件只需重标定"——那句要 GPU 云主机（B2）来证。

## 五、真正需要的 GPU 实验（B1 / B2）

这两项**必须租 GPU**，这台服务器帮不上：

| 实验 | 需要 | 参考价格 | 时间 |
|---|---|---|---|
| **B2** 第二块 GPU | 单卡 4090（24G）或 A100（40G） | 4090 约 2–4 元/时；A100 约 10–20 元/时 | 2–3 小时 |
| **B1** vLLM 对照 | 同上（vLLM 要 HF 权重，1.5B/3B 即可） | 同一次租机可合并做 | 3–4 小时 |

**建议一次租 4090 跑 4 小时（约 10–15 元），把 B1 和 B2 一起做完。**

环境建议：
- 选**预装 PyTorch/CUDA** 的镜像（省 30 分钟装环境）
- 开 JupyterLab 或直接 SSH
- 装完 vLLM 后先 `nvidia-smi` 确认显存
